# S3 Storage

S3 Storage is a Concrete CMS package that adds an Amazon S3-compatible storage location type for file uploads and media. It is designed for packages that need a cloud-backed storage backend without leaving the standard Concrete file storage workflow.

## Features

- Adds an S3 storage type for Concrete file storage locations
- Supports AWS S3 credentials and region configuration
- Optional CloudFront URL override for public file URLs
- Default region and API version values for quick setup
- Dashboard helper page for moving files between storage locations
- Compatible with Concrete CMS 9.5+ and PHP 8.4+

## Requirements

- Concrete CMS 9.5 or later
- PHP 8.4+
- Composer dependencies installed via the package
- An AWS S3 bucket and IAM credentials with access to that bucket

## Installation

Clone or install the package into your Concrete CMS project and run Composer:

```bash
composer install
```

If you are installing it as a package in a Concrete site, add the package to your project in the usual way for your setup. Once installed, the package registers a storage type named `S3 Storage` and creates a dashboard page at `/dashboard/s3_storage`.

## Package setup

After installation, open the Concrete CMS file storage settings and create or edit a storage location.

Choose the `S3 Storage` type and complete the following fields:

- Storage Bucket: the S3 bucket name
- Cloudfront URL: optional public base URL for generated file links
- Access Key: AWS access key ID
- Access Secret: AWS secret access key
- Amazon S3 Region: bucket region, for example `eu-west-2`, `us-east-1`, etc.
- API Version: AWS API version, default `2006-03-01`

The package includes default values for region and API version if they are left empty:

- Region: `eu-west-2`
- API version: `2006-03-01`

## CloudFront behavior

If a CloudFront URL is supplied, file URLs will use that value as the base URL for public access:

```php
https://cdn.example.com/ + /path/to/file.jpg
```

This avoids exposing the raw S3 hostname in generated public asset URLs.

If the CloudFront URL is empty, the package falls back to the AWS S3 object URL generated by the SDK.

## Moving files between storage locations

The package includes a dashboard page for migrating files from one storage location to another.

Navigate to:

```text
/dashboard/s3_storage
```

Select:

- the current storage location
- the destination storage location

Then submit the form. The controller gathers the files in the source location and dispatches a batch command to move each file record to the target storage location.

This is useful when switching from local or other storage backends to S3, or when moving files from an older bucket to a new bucket.

## Package structure

```text
.
├── composer.json
├── controller.php
├── src/
│   ├── Command/
│   ├── Concrete/
│   └── Package/
├── controllers/
├── elements/
├── tests/
└── README.md
```

Key implementation points:

- `controller.php` registers the package and installs the S3 storage type and dashboard page.
- `src/Concrete/File/StorageLocation/Configuration/TypeS3Configuration.php` defines the S3 configuration object and public URL generation.
- `src/Command/MoveStorageLocationCommand.php` and its handler move file records between storage locations.
- `tests/` contains the package's PHPUnit coverage.

## Development and testing

Or directly:


## Troubleshooting

### Region validation fails

Ensure the region value matches one of the allowed AWS regions registered by the package. If left blank, the package defaults to `eu-west-2`.

### URLs are not using CloudFront

Check that the `cloudfrontUrl` field is populated exactly as the public URL base, without any missing trailing slash handling. The package normalizes the URL before appending the file path.

### S3 authentication errors

Verify that:

- the bucket name is correct
- the IAM access key and secret are valid
- the key has permission to read and write the target bucket
- the configured region matches the bucket region
